# HTTP/2 and HTTP/3

cursed-http includes HTTP/2, HTTP/3 and a QUIC transport. The headers are written in
the same style as the rest of the repo:
- header-only;
- sans-IO: bytes in, events out, bytes to send;
- the caller owns the memory.

They are tested against the reference implementations nghttp2, nghttp3 and ngtcp2, against the
RFC examples, and against h2spec.

| header | what | depends on |
|---|---|---|
| [`hfield.h`](include/hfield.h) | SIMD header-field validation (AVX-512, AVX2, NEON, SWAR), Huffman codec, branchless QUIC varints | nothing |
| [`hpack.h`](include/hpack.h) | HPACK (RFC 7541) decoder with a dynamic table, encoder for responses | hfield.h |
| [`hreq.h`](include/hreq.h) | request header rules shared by HTTP/2 and HTTP/3 (RFC 9113 §8, RFC 9114 §4) | hpack.h |
| [`h2.h`](include/h2.h) | HTTP/2 server connection (RFC 9113) | hpack.h, hreq.h |
| [`qpack.h`](include/qpack.h) | QPACK (RFC 9204) decoder with a dynamic table, encoder for responses | hpack.h |
| [`h3.h`](include/h3.h) | HTTP/3 server (RFC 9114) over abstract QUIC streams | qpack.h, hreq.h |
| [`qhp.h`](include/qhp.h) | QUIC header-protection masks, batched (AES-NI, ARMv8 AES, ChaCha20 AVX2/NEON) | nothing |
| [`quic.h`](include/quic.h) | QUIC v1 server transport (RFC 9000/9001/9002) | hfield.h, qhp.h, **picotls + OpenSSL libcrypto** |

## Design

- **Memory is the caller's.**
  - `hpack.h`, `qpack.h`, `h2.h` and `h3.h` never allocate. The connection structs have fixed sizes,
    set by `H2_MAX_STREAMS`, `H2_STAGE` and similar macros.
  - Decoding works in a per-thread scratch area, not per connection. An `h2_conn` is about 37 KiB
    with the defaults.
  - `h2_recv` consumes a HEADERS frame only together with all its CONTINUATIONs, so a header block
    never has to be buffered per connection.
  - `quic.h` grows its stream buffers through a caller-supplied allocator, up to the flow-control
    windows it advertises. picotls allocates its own handshake state.
- **Validate once, then cache the verdict.** Every header name and value is checked by `hfield.h`'s
  SIMD validator when it is first decoded. The verdict is stored with the dynamic-table entry, so an
  indexed field is never scanned again (h2o's approach). nghttp2 and nghttp3 instead re-check every
  byte of every header on every request.
- **Dynamic tables in one block.** Descriptors sit in a ring and strings in a byte store that is
  compacted when it fills (HAProxy's approach).
- **The response encoders keep no dynamic table** (as in HAProxy): static references, then literals,
  Huffman-coded when shorter. The HTTP/2 encoder announces table size 0 once.
- **Zero-copy response bodies.** The application passes a pointer, which must stay valid until the
  stream's `on_close` or `on_sent`.
- **Backpressure.** `h2_recv` stops at a frame boundary once half of `H2_STAGE` is waiting to be
  sent. A response made from a callback therefore always finds room.
- **`h3.h` knows nothing about QUIC.** The transport hands it in-order stream bytes with their offsets
  and pulls per-stream output. So `h3.h` runs on `quic.h` or on any other QUIC stack.
- **`quic.h` is a server transport, sans-IO:**
  - `quic_accept` / `quic_recv` take datagrams, `quic_send` produces them, and
    `quic_timeout` / `quic_on_timeout` is the timer;
  - the TLS 1.3 handshake is picotls's;
  - packet protection is its own: AEAD through picotls, header protection through `qhp.h`.

## Status: what is tested, what is not

Nothing here is formally verified. It is tested, in these ways.

| part | tested against |
|---|---|
| hpack.h | **RFC 7541 Appendix C** (all 12 examples, decoded fields and table sizes, extracted from the RFC text by `gen/gen_rfc7541.py`). 12,000 blocks from nghttp2's deflater (random fields, table-size changes) decoded identically to nghttp2's inflater, table sizes in step. About 6,000 mutated blocks accepted or rejected alike. Cached verdicts equal fresh checks. Our encoder's output decodes under nghttp2's inflater |
| h2.h | **h2spec v2.6.0: 146/146, strict mode 147/147.** nghttp2's client in memory: browser GETs, gRPC POSTs with trailers, 1 MiB bodies through small client windows, a mid-connection INITIAL_WINDOW_SIZE change, 16–24 MB uploads, more than 100 concurrent streams, response header blocks larger than one frame, input cut at random points. Hand-built malformed requests and frames get the RST_STREAM / GOAWAY codes RFC 9113 asks for |
| qpack.h | **RFC 9204 Appendix B** (B.1–B.5: instructions, sections, sizes, our decoder-stream bytes, every cut of an encoder stream). The static table is extracted from RFC 9204 and checked against nghttp3's. 8,530 sections from nghttp3's encoder with a live dynamic table, acknowledged through our decoder stream. 544 mutated sections |
| h3.h | nghttp3's client over an emulated transport: GETs, bodies and trailers, the client's QPACK dynamic table, random input cuts and output sizes. Hand-built control-stream, QPACK-stream and request-stream errors |
| quic.h | **RFC 9001 Appendix A** (Initial keys, the client Initial decrypted, the server Initial protected byte-exact, the ChaCha20 short header, the key-update secret, A.2 through `quic_accept`). Frame-level errors (16 cases, connection and stream flow control). Building blocks (varints, packet-number windows, reassembly, send buffers, ACK ranges). **HTTP/3 over quic.h to an ngtcp2 + nghttp3 client** (picotls on both sides) over a simulated network: 20–150 requests per connection including 200 KB bodies and uploads, 0 / 2 / 10 % loss, reordering, duplicates, a client-initiated key update, a client blackholed after its first datagram. The 3× anti-amplification limit, and zero undecryptable packets |
| real clients | `make real-clients` (in CI): the example servers over real loopback sockets. **curl** (libnghttp2) over HTTP/2: 5 GETs multiplexed on one connection, a 1 MiB GET, a 300 KB POST. **aioquic 1.6.1** (an independent Python QUIC + HTTP/3 stack) over HTTP/3 with TLS 1.3: 40 GETs, a 1 MiB GET, a 300 KB POST, a client-initiated key update |
| all | **Planted bugs:** `make mutants-h2` (22 mutants over hpack/h2/qpack/h3) and `make mutants-quic` (10 over quic.h); every one must make a test fail. ASan + UBSan builds of the h2, qpack, h3 and QUIC tests |

**Limits and simplifications, plainly:**
- Server side only, for both HTTP/2 and HTTP/3.
- **HTTP/2:** no server push. PRIORITY is accepted and ignored (RFC 9113 deprecates it).
- **QPACK:** we advertise 0 blocked streams. A section that needs entries not yet received is a
  decompression error, not a wait.
- **QUIC, missing features:** QUIC v1 only (other versions get Version Negotiation), no 0-RTT, no
  Retry or address-validation tokens, no connection migration (PATH_CHALLENGE is answered on the
  current path), one connection ID per side, no ECN, no pacing.
- **QUIC, recovery:**
  - Congestion control is CUBIC (RFC 9438, with fast convergence and the Reno-friendly region).
    A packet declared lost and then acknowledged counts as a spurious loss. It raises the packet
    and time thresholds (up to 256 packets and 2 RTT), and if every loss of a congestion event
    was spurious, the window reduction is undone.
  - On the test network's 0–21 ms jitter, 100 requests take 1.1 simulated seconds. NewReno
    without undo took 78. With 2% loss on top it takes 11.8 s (was 64.8), and 60 requests at
    10% loss take 28.0 s (was 55.8).
  - Packet numbers are always sent in 2 bytes.
  - On PTO, everything outstanding is re-queued.
- **Real clients so far: curl (HTTP/2) and aioquic (HTTP/3).** Not yet tested against browsers, the
  QUIC interop runner or h3spec.
- The example servers are functionally tested by `make real-clients`, not load-tested.

## Performance

The comparison with more rivals (LiteSpeed's ls-hpack and ls-qpack, h2o, Rust's h2, Go's x/net/http2 and
quic-go/qpack) and an HTTP/3 server benchmark are in the README's
[HTTP/2 and HTTP/3 benchmarks](README.md#are-we-fast-http2-and-http3) (exp1380, exp1362). The table below is the
earlier nghttp2 / nghttp3-only run.

Xeon Platinum 8260 (Cascade Lake, 1 vCPU KVM), gcc 13.3 `-O3 -march=native`, exp1318.
- **Method:** `bench/bench_h2h3.c`, ns per request, best of 100 passes over 256 requests on one
  connection.
- **Everything is in memory:** no sockets and no TLS.
- **HTTP/2 server:** the same nghttp2-client byte stream goes into `h2.h` and into an nghttp2 server
  session. Both answer `:status 200` with a 13-byte body; only the server's work is timed.
- **Header sets:** `bench/h2_headers.h`. Browser is a Chrome request with a 350-byte cookie; gRPC is
  a grpc-go unary call with a traceparent; h2load is what h2load sends.

AVX2 build (`hv` backend avx2):

| set | HPACK decode: nghttp2 → hpack.h | HTTP/2 server: nghttp2 → h2.h | QPACK static-only: nghttp3 → qpack.h | QPACK dynamic: nghttp3 → qpack.h |
|---|---|---|---|---|
| browser | 640 → 355 ns (1.80×) | **2,337 → 525 ns (4.45×)** | 4,001 → 2,639 ns (1.52×) | 1,740 → 1,266 ns (1.37×) |
| gRPC | 1,230 → 546 ns (2.26×) | **2,437 → 703 ns (3.46×)** | 1,922 → 1,271 ns (1.51×) | 1,617 → 1,071 ns (1.51×) |
| h2load | 135 → 62 ns (2.17×) | **954 → 194 ns (4.91×)** | 334 → 133 ns (2.51×) | 207 → 85 ns (2.43×) |

With `-DHV_USE_AVX512`, HPACK decode improves a little (browser 326 ns, h2load 52 ns) and the rest is
unchanged, within noise.

- **Where the HTTP/2 gain comes from:**
  - validate-once instead of nghttp2's per-request re-validation;
  - no per-header allocation or refcounting;
  - decoding into scratch memory;
  - an encoder without a dynamic table.
- **No whole-server comparison yet.** These are library-only numbers: a server's share of
  per-request CPU also includes syscalls and TLS, and nothing here measures that.
- **Static-only QPACK** is what a client sends when the server advertises no table. It is dominated
  by Huffman decoding, which is about as fast as it gets without a wider table.
- **QUIC is not benchmarked yet.

## Build and test

```bash
scripts/fetch-thirdparty.sh nghttp2 nghttp3 h2spec picotls ngtcp2
make test-h2h3          # every HTTP/2 / HTTP/3 / QUIC test
make h2spec             # needs Go
make real-clients       # curl + aioquic against the example servers (needs curl, openssl, python3-venv)
make mutants-h2 mutants-quic
make build/h2h3/bench_h2h3 && build/h2h3/bench_h2h3
```
